# Specification Artifact

A specification artifact should be a small, focussed document that defines
an aspect of what we're trying to build. The main goal of the spec is to convey
intent, and defines boundaries for what the result should look like. A spec
does not need to be exhaustive or prescriptive, as decisions and refinements
can be made during implementation.

What good looks like:
- *Clear*: shows the intent, the design decision and the perimeter of the implementation
- *Consistent*: in structure, length, formatting and terminology with other specs.
- *Compact*: human-readable, clear, paragraphs, bullet-points.

What to avoid:
- *Verbosity*: this is not prose, prefer lists and tables to long paragraphs.
- *Plan*: a specification is not an implementation plan, the plan will refine
  and interpret the specification in the context of the code base, and possible
  make decisions.
